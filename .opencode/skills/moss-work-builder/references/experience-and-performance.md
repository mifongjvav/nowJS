# 跨端体验与性能

## 嵌入式视口

PICKCAT 默认播放器为 16:9 容器，展开时占满可用视口；这不要求作品固定 16:9，更不意味着作品能控制整个浏览器。
以 iframe 自己的宽高布局，处理窄屏、横竖屏与动态 resize。画布保留自己的逻辑坐标并按容器缩放；不要硬编码外层网页宽度。

保留标准 viewport 声明，不禁止用户缩放。控件可用键盘和触摸操作，显示焦点；触摸手势只占用必要区域，避免整页禁用滚动。文本输入避免被全局快捷键劫持。Canvas/WebGL 要有失败提示，长列表和文本不能只因缩小播放器就被截掉。

外层全屏/展开由平台控制；作品内部不要重复绘制一套 PICKCAT 导航、登录或发布界面。

## 媒体与生命周期

音频、WebAudio 和媒体播放从真实点击/触摸启动；捕获 `play()` 拒绝并给用户重新开始入口。不要假设外层允许 autoplay 就能自动播放。

使用 page visibility / 页面生命周期暂停不必要的计算、音频和动画，并清理计时器、事件、Blob URL、Worker、音频与 GPU 对象。平台离开页面、切换作品或收回播放资格会销毁会话；及时保存重要进度，不能依赖关闭瞬间一定完成异步写入。

尊重 reduced-motion，作品核心交互仍应可理解。设备能力不足时降低分辨率、帧率和粒子等负载，控制 devicePixelRatio；没有硬 CPU/内存配额不代表可无限占用。

## 加载预算

全部上传文件都会下载、校验和准备，再开始初始脚本。未引用的大素材也占额度；压缩 ZIP 小不代表下载和 Blob 内存小。减少死文件、超大图片、静态数据库和 Base64；对媒体使用浏览器能解码的合适格式。代码压缩不能代替去除不支持的库分支。

SDK 初始握手 5 秒、会话装载总预算 30 秒；player 有自己的下载和启动计时。不要用永不完成的 TLA、同步大循环或初始等待用户操作阻断 ready。`ready` 仅保证初始脚本/模块执行，不保证后续业务、媒体和异步交互。

## 验证清单

- 结构审计、可用时的真实 SDK prepare、MOSS 私有预览、PICKCAT 公开播放分开记录。
- 测试实际 ZIP 对应版本的首次进入、权限允许/拒绝、加载错误和重新开始。
- 检查窄屏、横屏、默认播放器和展开状态；验证滚动、触摸、键盘和焦点。
- 验证声音需手势时仍可操作、GPU/媒体失败时能恢复。
- 分别验证显式存档、localStorage、刷新、公开版本更新和预览版本隔离；无浏览器/平台访问时列为待验证。
- 不将不同浏览器、手机、线上部署写成已验收，除非本次确实观察到。
